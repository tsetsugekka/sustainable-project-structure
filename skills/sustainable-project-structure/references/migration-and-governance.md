# 迁移与治理

## 先盘点再移动

1. 读取项目指令和版本控制状态，保留用户未提交修改。
2. 列出根目录、两层子目录、最大目录、缓存、临时目录和散落文件。
3. 搜索源码、测试、文档、部署清单和定时任务中的旧路径；识别程序读取的 Markdown 路径和字段，它们也属于接口。
4. 将内容分为：正式保留、移动归类、复用资产、项目 Skill、归档、临时、可删除缓存、待用户判断。
5. 对运行时路径、部署源、唯一原稿、敏感文件和外部同步目录提高风险等级，不凭名称猜测。

## 根目录治理

- 根目录只保留固定分类入口和少量治理文件。
- `PROJECT_STRUCTURE.md` 或既有治理文档记录目录职责和落位规则；白名单、编号只在项目采用时维护。
- `AGENTS.md` 或 `CLAUDE.md` 链接权威规则，要求结构、文档和相关检查在同一变更同步；具体授权遵循用户指令与项目边界。
- 新增根目录前先检查已有职责能否承接，确有需要时说明理由；不为已授权的常规整理重复设置审批。
- 为稳定结构提供自动检查；检查规则必须与文档同一任务更新。

## 旧路径索引

- 使用 `MOVED_PATHS.md` 或项目既有名称。
- 只记录已有路径的移动、重命名、合并或被替代删除。
- 每条记录从旧路径直接指向当前最终路径，附简短原因。
- 普通新建文件不登记；日常任务不预读索引。
- 只有旧会话引用失效或预期文件不存在时才查询，仍找不到再搜索全项目。

## 临时生命周期

- 当前任务使用 `99_Temporary/YYYYMMDD-topic/` 或系统临时目录。
- 任务中间物在收尾清理；仅在实际保留义务、敏感数据期限或恢复需求存在时设置复核日期。
- 收尾时把有价值的内容提升到正式所有者目录，其余删除。
- 最终交付物、唯一原稿和 Skill 权威源不能只存在于临时目录。
- 缓存、已安装依赖、系统元数据和可再生构建树按项目规则处理；依赖清单与锁文件通常属于可再现性来源，应跟踪保留。

## 项目 Skill 可再现性

- 只指定一个权威目录，例如 `.agents/skills/<name>/` 或项目明确约定的 `92_ProjectSkills/<name>/`。
- 保持 `SKILL.md`、`agents/`、`references/`、`scripts/`、`assets/` 的相对路径完整。
- 不把 live token、Cookie、密码、个人资料或本机绝对路径写入 Skill。
- 本地连接配置单独忽略；发布包使用临时副本，不能反向覆盖权威源。
- 新增或修改 Skill 后执行格式验证、脚本测试和一次贴近真实任务的试运行。

## 迁移后验证

- 搜索所有旧路径；仅允许迁移索引和明确的历史记录继续出现。
- 确认新路径文件数量、关键文件哈希或版本控制 rename 对应关系。
- 按受影响范围运行原有测试、构建、lint 和结构检查；纯文档变更不要求全站构建或生产执行。
- 对部署清单逐条确认本地源存在，不执行未获授权的线上发布。
- 检查根目录没有重新出现 `tmp`、`work`、`outputs`、`generated`、`downloads` 等临时入口。
- 用最终目录树和迁移索引向用户交付，不把大量中间移动过程当成最终结构。

## 文档整理的额外验证

遵循 [文档生命周期](documentation-lifecycle.md)，先做内容去重与归档，再验证导航。确认独有规则、待办和恢复步骤有承接；不把已结束记录的旧规则当成当前约束。修改文档路径前同步机器消费者。自动索引与链接检查各自验证职责，短期文档无需从根入口可达。
