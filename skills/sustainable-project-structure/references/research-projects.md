# 企划、调查与分析项目结构

## 目标

围绕事实来源、工作流和交付关系组织资料，使会议、分析、原始资料、可编辑源文件、正式交付物和方法沉淀彼此可追溯。

## 推荐分区

编号和语言应适配项目实际业务。典型结构：

```text
01_Research/              # 调查、分析、SQL、工作底稿
02_Meetings/              # 会议记录和已确认决策
03_Sources/               # 非临时、允许保存的事实来源
04_Deliverables/          # 正式交付物及可编辑源文件
80_Reference/             # 企划和背景参考
90_ReusableAssets/        # 已验证的方法、模板、清单、固定脚本
.agents/skills/           # 项目级 Skill 的唯一权威源（可按现有规则调整）
98_Archive/               # 停止活跃但仍需追溯的非敏感资料
99_Temporary/             # 当前任务中间物、转换缓存和试验
```

已有清晰业务分类时，应保留团队熟悉的业务名称，例如数据分析、会议、业务资料、客户资料和开发子项目；不要为了套模板破坏已经形成的检索习惯。项目按稳定工作流分类时，可让事实来源、分析方法、评审记录、企划资料和复用资产各自成为固定入口。

## 文档策略

- 每个稳定根分区维护 `README.md`，说明收什么、不收什么、输入输出和敏感边界。
- 一个主题包含多个文件时，使用 `YYYYMMDD_主题/README.md` 记录来源、文件关系、生成方式、推荐版本和注意事项。
- 有独特证据或交接价值的分析任务可保存记录，写明目的、适用时间、假设、决策、输出和局限；日常修订优先更新原文。
- 不要求所有文件夹维护 `SPEC.md` 或 `CHANGELOG.md`。其中持续维护的软件、网页、自动化工具子项目按复杂度承担开发文档职责。
- 事实、推测、会议意见和最终决策必须区分；不要让临时分析结论覆盖权威来源。

## 临时、归档与敏感资料

- 工具生成的 `outputs/`、预览图、OCR 文本、下载副本和中间导出统一进入任务临时目录。
- 最终交付物不能只在临时区；保留可编辑源文件、关键输入和最终版本之间的关系说明。
- 可重新生成、重复或无解释价值的内容删除；仍需追溯的非敏感旧版本进入归档。
- 候选人、客户、个人绩效、会议原文、凭据等敏感输入遵循项目安全规则；若只为当前任务使用，任务结束即删除临时副本，不自动归档。

## 方法与 Skill 的边界

- 值得复用或追溯的单次经验保留在主题 README 或所属记录；不为每次任务机械写日志。
- 经多次验证、跨任务复用的方法进入 `90_ReusableAssets/`。
- 触发条件、工作流、输入输出、安全边界稳定后，再创建项目级 Skill。
- Skill 只保存抽象方法和脱敏示例，不依赖具体客户资料、个人文件或临时目录。

## 混合项目

若企划项目内包含网页、Dashboard 或自动化工具，将它放进一个明确的开发区或独立子项目；在该子项目内部使用开发单元所有权和按需文档职责。研究原始资料仍留在研究分区，通过 README 或配置记录输入路径，不复制到源码树中。

## 文档生命周期

遵循 [文档生命周期](documentation-lifecycle.md)：长期方法与来源说明原位维护，阶段分析与会议记录保留时间和适用范围；根入口导航稳定工作流，短期批次不进入根清单。归并前保留独有证据和未决问题，自动目录来自文件路径与标题，不重复维护文件总表。
