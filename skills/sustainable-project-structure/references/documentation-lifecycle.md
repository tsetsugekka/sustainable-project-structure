# 分布式文档库的可持续维护

目标是让现行知识少而可信、历史可追溯、目录随文件变化。文档留在责任模块；根目录只是导航，不是全部 Markdown 的收容处。沿用项目既有命名，下面是职责而非必建文件清单。

## 内容归属与时效

| 职责 | 应保存的内容 | 维护方式与入口 |
| --- | --- | --- |
| 长时效指南／规格 | 持续适用的行为、契约、操作和可复用方法 | 行为变化时原位更新；根入口链接模块入口及少量跨模块指南 |
| 当前任务 | 目标、未完成项、阻塞、下一步、实现与验证边界 | 更新既有任务入口；完成批次的日志和证据移出，保留真实待办 |
| 短时效记录 | 值得保留的实验、复杂迁移、事件调查或分阶段交接 | 标明时间、适用范围、结论及证据；留在模块 records/history 或等价位置，不进入根目录清单 |
| 历史资料 | 已结束、被替代、退役但仍有追溯或恢复价值的资料 | 标明历史状态和现行替代入口；保留原始证据，不当作现行规则不断改写 |
| 变更日志 | 重要变化、日期与发布状态 | 简述并链接规格或记录，不复制整份规格、测试日志和恢复步骤 |
| 临时产物 | 下载、诊断、转换缓存和试验中间物 | 优先系统临时目录；收尾清理本次无用产物，有恢复价值的按项目备份规则保存 |

长时效表示承担持续维护责任，不保证内容永不改变。短时效不等于很快删除：一份结束的实验可以长期留作证据。到期、复核和清理日期只在真实外部时限或恢复义务需要时添加，不为每篇文档机械设期限。

模块操作、现行规格与变更可以是 README、SPEC、CHANGELOG，也可以沿用等价文件或较小项目的一份文档；不要为目录对称制造空文件。任务、方案、实现、验证、发布和运行验收分别表述，不把局部测试通过写成线上已完成。

## 创建前的判断

1. 搜索主题与责任模块，优先更新已有权威位置。相同事实在其他位置链接引用。
2. 新长期文档须有独立职责和持续读者；单次修改、方向调整或日常内容修正通常只需更新原文和必要变更日志。
3. 新记录须有独特证据、恢复用途、可复用经验或交接价值。必要备份的恢复信息随备份清单保存，不为每次操作另写报告。
4. 未实现方案须明确标识；产生实际结果后，把有效契约写回现行来源，将剩余待办写回任务入口。

## 去重、合并与归档

以主题为单位比较正文，先明确权威来源。小项目可直接在差异中审查，大批量时用临时清单记下“原位置 → 保留内容 → 目标位置”，无需新增永久总表。

- 重复规则合并到责任来源；保留独有结论、约束、未完成项、证据和恢复步骤后，才删除重复文件或段落。
- 遇冲突查实现、生成源和适用时间；较新的说明并不自动正确。不确定的内容标为历史或待核实，不伪装成现行规范。
- 从历史中提炼稳定方法进入长期指南，批次参数、过程日志和一次性失败留在原记录。必要时只为原记录补充勘误或替代链接。
- 已在 records/history 的结束记录通常无需再移动。只有退役模块、错误归属或影响现行检索时才调整位置；不得仅凭年龄、无人引用或“看起来旧”删除。
- 移动或合并同步修复相对入链和出链、标题锚点及实际引用方。Markdown 也可能是构建或部署程序的输入；发现脚本读取文件或字段时，把它视作接口，保留兼容或在同一变更迁移消费者。
- 不把内部指南、日志、凭据或生产快照混入公开网页／技能包。公开经验只保留可迁移的方法，改用中性示例；检查原文件、脚本、测试夹具和最终包，而非只检查新增段落。

## 自动目录的最小契约

优先扩展项目已有工具；无工具时可用本 skill 的 `scripts/doc_index.py` 模式。目录生成来源是文件路径与 H1，而非另一份逐文件登记表。只配置稳定的收录范围与职责边界。

- 根入口列模块入口和长期共享知识。短时效、历史、任务流水与变更日志从模块入口、局部记录索引或路径搜索查阅；不以“所有 Markdown 从根可达”为目标。
- 模块索引按所属范围生成；大量历史记录确需局部索引时，在历史目录单独生成，不把它们提升到根清单。少量历史记录可以直接链接，无需为了可达率创建索引链。
- 只替换显式标记之间的区域，保留人工目的说明；标记缺失或不成对时报告错误，不覆写全文。生成器不负责推断业务真伪或自动归档。
- 相同输入产生相同输出，不写每次执行时间。新增、删除、重命名和标题变更都必须反映出来；只读检查发现不一致时失败，写入模式可重建目录。
- 从版本控制清单或明确责任范围扫描，排除依赖、构建物、被忽略文件、独立仓库及无关 Markdown 数据；已删除的跟踪文件不应造成读取失败。
- 检查既有本地链接，包括未进入根索引的短期文档。外链检查和业务验证另计；目录检查通过不意味着这些检查完成。

脚手架会为新项目安装本地生成器并写入真实命令。已有项目先决定范围、接入已有工具，再写入 AGENTS；不要留下未实现的命令占位。任务收尾执行是一种自动维护流程，但没有接入 hook、CI 或监听器时，必须如实说明触发方式；无需为此新增后台服务。

## AGENTS 的职责与验收

AGENTS / CLAUDE 只保留触发规则、唯一文档政策入口和实际执行命令，详细原则集中在政策来源。要求 Agent：开工读相关来源；变更时更新受影响事实；收尾整理待办、生成并检查索引、审查差异，一起交付。

完成时至少检查：

- 重复事实确已归并，独有内容和恢复价值保留；当前任务中留下真实未完成项。
- 根入口没有短期批次清单；模块文档留在归属处，历史状态与现行替代入口清楚。
- 新增、改名、改标题、删除后只读检查能报过期；重建两次第二次无差异，人工区域不变。
- 移动后的入链、出链和机器读取继续有效。按变更运行相关检查，不为了纯文档整理触发生产任务。
